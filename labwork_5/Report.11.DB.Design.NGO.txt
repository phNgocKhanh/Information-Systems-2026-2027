REPORT 11 - NGO DATABASE DESIGN

1. INTRODUCTION

This database is designed to manage projects of a Non-Governmental Organization (NGO).

The database stores information about head offices, projects, actions, cities, and investments.

2. CONCEPTUAL MODEL

The database has four main entities:

- Head_offices: Stores information about head offices.
- Projects: Stores information about projects.
- Action: Stores actions belonging to projects.
- City: Stores information about cities.

Relationships:

- One head office manages many projects (1:N).
- One project contains many actions (1:N).
- One action can take place in many cities (N:M).
- One city can have many actions.
- One project can invest in many cities (N:M).

Two additional tables are used to solve the many-to-many relationships:

- Action_of_city
- Project_city_budget

Assumptions:

- Each project is managed by one head office.
- Each action belongs to one project.
- Each project-city pair has one investment amount.

3. LOGICAL MODEL

The database contains six tables.

Table 1: Head_offices

Primary Key: head_office_id

Attributes:
head_office_id, city, country, address, phone, director_name

Table 2: Projects

Primary Key: project_id

Foreign Key:
office_id references Head_offices(head_office_id)

Attributes:
project_id, code, title, start_date, end_date,
budget, person_in_charge, office_id

Table 3: Action

Primary Key: action_id

Foreign Key:
project_id references Projects(project_id)

Attributes:
action_id, project_id, description

Table 4: City

Primary Key: city_id

Attributes:
city_id, city_name, country, population

Table 5: Action_of_city

Composite Primary Key:
(action_id, city_id)

Foreign Keys:
action_id references Action(action_id)
city_id references City(city_id)

Table 6: Project_city_budget

Composite Primary Key:
(project_id, city_id)

Foreign Keys:
project_id references Projects(project_id)
city_id references City(city_id)

Attributes:
project_id, city_id, investment

5. SQL COMMANDS


CREATE DATABASE IF NOT EXISTS ngo;
USE ngo;

-- Table 1: Head_offices
CREATE TABLE Head_offices (
    head_office_id INT PRIMARY KEY,
    city VARCHAR(100),
    country VARCHAR(100),
    address VARCHAR(100),
    phone VARCHAR(100),
    director_name VARCHAR(100)
);

-- Table 2: Projects
CREATE TABLE Projects (
    project_id INT PRIMARY KEY,
    code VARCHAR(100),
    title VARCHAR(100),
    start_date DATE,
    end_date DATE,
    budget DECIMAL(15,2),
    person_in_charge VARCHAR(100),
    office_id INT,
    FOREIGN KEY (office_id)
        REFERENCES Head_offices(head_office_id)
);

-- Table 3: Action
CREATE TABLE Action (
    action_id INT PRIMARY KEY,
    project_id INT,
    description VARCHAR(100),
    FOREIGN KEY (project_id)
        REFERENCES Projects(project_id)
);

-- Table 4: City
CREATE TABLE City (
    city_id INT PRIMARY KEY,
    city_name VARCHAR(100),
    country VARCHAR(100),
    population INT
);

-- Table 5: Action_of_city
CREATE TABLE Action_of_city (
    action_id INT,
    city_id INT,
    PRIMARY KEY (action_id, city_id),
    FOREIGN KEY (action_id)
        REFERENCES Action(action_id),
    FOREIGN KEY (city_id)
        REFERENCES City(city_id)
);

-- Table 6: Project_city_budget
CREATE TABLE Project_city_budget (
    project_id INT,
    city_id INT,
    investment DECIMAL(15,2),
    PRIMARY KEY (project_id, city_id),
    FOREIGN KEY (project_id)
        REFERENCES Projects(project_id),
    FOREIGN KEY (city_id)
        REFERENCES City(city_id)
);
